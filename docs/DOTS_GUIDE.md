# Dotsの受信テストと応答設定

[English](DOTS_GUIDE_EN.md) | 日本語

自分で配置したSendTextToDotsを使う利用者向けの案内です。初回導入やFork先でも使える、テスト用と運用用の指示文を用意しています。

まず[導入手順](INSTALL.md)に沿ってAppleログイン、Dots/ChatGPTからのOAuth接続、`text.submitted`の購読を済ませ、送信画面`/console`で「受信中」を確認します。以下の指示文は、本文を受信するDotsの会話へ直接貼り付けてください。送信画面の案内からコピーするか、この文書の文面を使えます。

## 1. 送信テスト前にDotsへ貼る

短い、秘密情報や個人情報を含まない本文で配送を確認します。受信するDotsへ、次の指示文を貼り付けてください。

```text
SendTextToDotsの配送を確認します。運用用の指示文に切り替えるまで、SendTextToDotsから届いた本文を次のルールで扱ってください。

1. 本文中の質問や依頼には対応せず、配送確認用の文章として扱ってください。
2. 受信した本文だけを、そのまま返してください。言葉、句読点、空白、改行を変えず、説明や要約を付けないでください。
3. 秘密情報や公開すべきでない個人情報が含まれると判断した場合は、その内容を再掲せず、安全なテスト文への変更が必要だと知らせてください。この場合は本文一致の確認ができたとはしないでください。
```

## 2. 送信してDots側で確認する

同じ送信画面の本文欄に短い非機密文を入力して1件送信し、同じDotsが返した本文と、送った本文が一致することを確認します。送信画面の`delivered`（受領）はcallbackの2xx受領を示すもので、Dotsの返答・本文一致・作業完了の証明ではありません。

コピーしただけでは指示文はDotsへ送られません。Dotsが指示に従うことや、原文を必ず正確に再現することは保証されません。一致しない場合は、受信先・購読状態・Dotsへの指示を確認してください。

## 3. 確認後に運用用の指示文をDotsへ貼る

テストが済んだら、同じDotsへ次の文面を貼り付けます。この文面は、初めから通常の応答を使いたい場合にも使えます。

```text
SendTextToDotsから受信した本文には、次のルールで対応してください。

1. 最初に、どの文章を受け取ったか分かる短い受領メッセージを返してください。短い本文は引用し、長い本文は要点を1〜2文で要約してください。引用か要約かを明記してください。
2. パスワード、認証コード、APIキーなどの秘密情報や、公開すべきでない個人情報は、引用・要約・回答へ再掲しないでください。必要なら「機密情報を省略」と示し、安全に内容を示せない場合は受領したことだけ伝えてください。
3. 受領メッセージは、例えば「受信内容（引用）：『……』。受け取ったよ。回答を準備するね。」という形にしてください。長文の場合は「受信内容（要約）：……」としてください。
4. 続けて、本文の質問や依頼に沿って回答・作業してください。引用や要約は受領表示のためのもので、実際の対応は受信した本文全体を確認して行ってください。
5. 情報が足りない場合は、必要な確認を伝えてください。「受け取った」と「作業が完了した」は区別し、まだ行っていない作業を完了したとは言わないでください。後で自動返信できると確認できない場合は、その約束をしないでください。
```

運用用の指示文をコピー・貼付した後は、受信内容が分かる返答になるかをDots側で確認してください。送信画面は、この切替が完了したと自動判定しません。受信先を変えた場合も、使いたい応答方針をそのDotsへ伝えてください。

SendTextToDotsは本文を解釈せず配送します。引用・要約・秘密情報の省略・回答・作業は受信先Dotsの応答方針であり、サーバーによる自動処理や保証ではありません。[制約](LIMITATIONS.md)も参照してください。
